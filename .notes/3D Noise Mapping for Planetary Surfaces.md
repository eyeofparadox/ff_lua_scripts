

The Perlin noise API implements a well-known, award-winning noise algorithm that offers smoother, natural-looking noise with adjustable scale. The core of this API is the get_perlin_noise() function which accepts three coordinates (there is an "animated" Z coordinate example on the Noise API page) and a scale factor, and returns a single value representing the noise amplitude at the sample coordinates. The noise generated by the Perlin noise API can be made seamless. You can even specify the region to be tilable. The main drawback is that the Perlin noise API offers only a single-octave noise, so if you want a more complex noise you'll have to implement the layering yourself. On the Noise API webpage, there is an example filter that emulates Filter Forge's built-in multi-octave Perlin noise via the script API. I've used it before, but I think it's better to use our own approach to accommodate my ideas better. I definitely think we could look into the scale factor, since it probably plays well with the native seamlessness. 

My interest in developing +dimension-based-loop-seamlessness is to support my custom approaches to Perlin, Worley and Simplex noises (2D, 3D, 4D).

		local w = self.fade(z)

function gen_perlin_octaves(ch_noise, ch_roughness, ch_contrast, ch_distortion, ch_noise_x, ch_noise_y, ch_noise_z)
	local distortion = 0
	ch_roughness = set_ch_roughness(ch_roughness)
	ch_contrast = ch_contrast  * 2 - 1
	factor = (259 * (ch_contrast + 1)) / (1 * (259 - ch_contrast))
	NOISE_SIZE = (((rs + gs + bs + as) * 0.25) ^ 2) 
	OCTAVES = {}
	local cell_size = (0.01 + NOISE_SIZE * 0.99) * grain
	local scale = ch_roughness
	local octave_index
	for octave_index = 1, OCTAVES_COUNT do
		if (scale < ROUGHNESS_THRESHOLD) then
			OCTAVES_COUNT = octave_index - 1
			break
		end
		OCTAVES[octave_index] = {cell_size, scale}
		cell_size = cell_size * 2.0
		scale = scale * ch_roughness
	end
	
	if (remainder >= 0.001) then
		OCTAVES[OCTAVES_COUNT][2] = OCTAVES[OCTAVES_COUNT][2] * remainder
	end

	NORM_FACTOR = 0
	for octave_index = 1, OCTAVES_COUNT do
		NORM_FACTOR = NORM_FACTOR + OCTAVES[octave_index][2] ^ 2
	end
	NORM_FACTOR = 1 / math.sqrt(NORM_FACTOR)
	
	local octave_index 
	for octave_index = 1, OCTAVES_COUNT do
		local size = OCTAVES[octave_index][1]
		local opacity = OCTAVES[octave_index][2]
		distortion = opacity * perlin:noise(rd + ch_noise_x * size,gd + ch_noise_y * size, bd + ch_noise_z * size)
		ch_noise = ch_noise + (opacity * perlin:noise(ch_noise_x * size,ch_noise_y * size, ch_noise_z * size )+ distortion)
	end

	-- contrast adjustments
	ch_noise = (ch_noise + 1.0) * 0.5
	ch_noise = truncate(factor * (ch_noise - 0.5) + 0.5)
	return ch_noise
end;


function set_ch_roughness(ch_roughness)
	ch_roughness = ROUGHNESS_THRESHOLD +  ch_roughness * (1.0 - ROUGHNESS_THRESHOLD)
	return ch_roughness
end;

function fromrgb(r, g, b)
	local max, min = math.max(r, g, b), math.min(r, g, b)
	local h, s, l

	l = (max + min) / 2

	if max == min then
		h, s = 0, 0 -- achromatic
	else
		local d = max - min
		local s
		if l > 0.5 then s = d / (2 - max - min) else s = d / (max + min) end
		if max == r then
			h = (g - b) / d
			if g < b then h = h + 6 end
		elseif max == g then h = (b - r) / d + 2
		elseif max == b then h = (r - g) / d + 4
		end
		h = h / 6
	end

 return h, s, l or 1
end


function truncate(value)
	if value <= 0 then value = 0 end
	if value >= 1 then value = 1 end
	return value
end;

### Key changes
- Introduce spherical → Cartesian conversion (`x, y, z` from `theta, phi, radius`).
- Then derive polar coordinates in the `x, y` plane (`radius`, `theta_polar`).
- Add an inversion checkbox for `z` so you can run north/south passes with identical settings.

Here’s a revised sketch of your `get_sample` function with the coordinate mapping swapped:

```lua
function get_sample(x, y)
    local r, g, b, a = get_sample_map(x, y, BACKGROUND)
    local r2, g2, b2, a2 = get_sample_map(x, y, FOREGROUND)

    local roughness = 3.75 - get_sample_grayscale(x, y, ROUGHNESS) * 4.375 + 0.01
    local contrast = (get_sample_grayscale(x, y, CONTRAST) * 2) - 1
    local factor = (259 * (contrast + 1)) / (1 * (259 - contrast))

    local osx, osy, osz, osa = get_sample_map(x, y, OFFSET)
    local dx, dy, dz, da = get_sample_map(x, y, DISTORTION)
    local sx, sy, sz, sa = get_sample_map(x, y, SCALE)

    local s = 500
    local amp = 1
    sx, sy, sz, sa = sx * 1.25, sy * 1.25, sz * 1.25, sa * 1.25

    -- spherical coordinates (rho, theta, phi)
    local radius = 1.0
    local theta = x * math.pi * 2   -- longitude
    local phi   = y * math.pi       -- latitude

    -- spherical → Cartesian
    local cx = math.cos(theta) * math.cos(phi) * radius
    local cy = math.sin(theta) * math.cos(phi) * radius
    local cz = math.sin(phi) * radius

    -- optional inversion for south hemisphere
    if get_checkbox_input(INVERT_Z) then
        cz = -cz
    end

    -- Cartesian → polar in xy-plane
    local pradius = math.sqrt(cx*cx + cy*cy)
    local ptheta  = math.atan2(cy, cx)

    -- feed noise with polar coords
    local nx = pradius * sx + (osx * osa)
    local ny = ptheta  * sy + (osy * osa)
    local nz = cz      * sz + (osz * osa)

    local v = 0
    for oct = 1, details do
        local d1 = get_perlin_noise(nx+1, ny, nz, s) * (dx * da)
        local d2 = get_perlin_noise(nx+2, ny, nz, s) * (dy * da)
        local d3 = get_perlin_noise(nx+3, ny, nz, s) * (dz * da)

        if oct == 1 then
            v = get_perlin_noise(nx+d1, ny+d2, nz+d3, s)
        else
            v = (v + get_perlin_noise(nx+d1/oct, ny+d2/oct, nz+d3/oct, s) * amp) / (1 + amp)
        end

        nz = nz * 2
        s  = s / 2
        amp = amp / roughness
    end

    v = truncate(factor * (v - 0.5) + 0.5)
    v = get_sample_curve(x, y, v, PROFILE)

    local opacity = v
    r, g, b, a = blend_normal(r, g, b, a, r2, g2, b2, a2, opacity, hdr)
    return r, g, b, a
end
```

### What this does
- **Two-pass workflow:** Run once with `INVERT_Z` unchecked (north hemisphere), then again with it checked (south hemisphere).
- **Noise continuity:** Because you’re feeding `pradius` and `ptheta` into the noise, the distortion wraps smoothly around the sphere instead of stretching at the poles.
- **Flexibility:** You can still scale/offset/distort as before, but now the mapping is polar‑aware.

This way, your Filter Forge noise becomes a true 3D polar surface, ready for erosion in World Machine without the seam artifacts of equirectangular projection.

## ⭐ What you’ve realized — stated cleanly  
You’re no longer thinking of polar Perlin as:

- a 2D noise function remapped into polar space  

You’re thinking of it as:

- **a 3D noise field sampled through a polar coordinate lens**,  
- where the *plane of sampling* (the circle) can move, rotate, tilt, or translate inside that 3D field.

This is the same conceptual leap that makes **volumetric clouds**, **planetary atmospheres**, and **nebulae** work — but now applied to *polar* sampling.

---

## ⭐ The coordinate system you’re describing  
You’re essentially defining a 3D coordinate system:

- **rho** — radial distance from the axis  
- **theta** — angle around the axis  
- **z** — height along the axis  

This is cylindrical coordinates, but you’re using it as a *polar sampling plane* inside a 3D Perlin domain.

Mathematically:

\[
x = \rho \cos(\theta)
\]
\[
y = \rho \sin(\theta)
\]
\[
z = z
\]

Then you sample:

\[
v = \text{Perlin}(x + \Delta x,\; y + \Delta y,\; z + \Delta z)
\]

Where the deltas come from:

- rotation  
- translation  
- domain warping  
- distortion maps  
- your existing offset/scale logic  

This gives you a **fully steerable 3D polar noise engine**.

---

## ⭐ Why this is so powerful  
Because now:

### **1. You can rotate the entire noise domain**
Rotate around x, y, or z:

- rotate the polar plane  
- rotate the noise field  
- rotate the sampling direction

**∝** is read as **“is proportional to.”**

In math language:

-  
  \[
  A \propto B
  \]

  **“A increases or decreases in the same ratio as B.”**

It does **not** mean equality — it means the relationship holds *up to a constant factor*.

  P(\rho) \propto \rho

- If ρ doubles, the density doubles.  
- If ρ shrinks by half, the density shrinks by half.

\[
P(\rho) = k \rho
\]

That constant \(k\) is usually chosen so the total integrates to 1.

# **1. Gradient Field Kernel**  
### 🧩 **What it is**  
A local convolution that extracts the **direction of steepest change** in the input shape.  
This gives you a **vector field** pointing toward the nearest boundary.

### 🎯 **What it does**  
- Detects edges  
- Computes direction to the boundary  
- Computes magnitude of change  
- Produces a vector (dx, dy) per pixel  
- Encodes this vector in RGB or RG channels  

This is your **“invisible angle‑map.”**

### 🧠 **How it works logically**  
You apply a small convolution kernel (Sobel, Scharr, Prewitt) to the input mask.  
This gives you:

- **gx** = ∂I/∂x  
- **gy** = ∂I/∂y  

The gradient vector:

\[
\vec{g} = (gx, gy)
\]

points **toward the nearest edge**.

### 📐 **Mathematical form**  
Using Sobel:

\[
gx = (I_{x+1,y-1} + 2I_{x+1,y} + I_{x+1,y+1}) - (I_{x-1,y-1} + 2I_{x-1,y} + I_{x-1,y+1})
\]

\[
gy = (I_{x-1,y+1} + 2I_{x,y+1} + I_{x+1,y+1}) - (I_{x-1,y-1} + 2I_{x,y-1} + I_{x+1,y-1})
\]

### 🧩 **FF map script prototype**
```lua
function gradient_field(x, y)
    local gx = sample(x+1,y-1) + 2*sample(x+1,y) + sample(x+1,y+1)
             - sample(x-1,y-1) - 2*sample(x-1,y) - sample(x-1,y+1)

    local gy = sample(x-1,y+1) + 2*sample(x,y+1) + sample(x+1,y+1)
             - sample(x-1,y-1) - 2*sample(x,y-1) - sample(x+1,y-1)

    return gx, gy
end
```

This produces a **vector field**.

# **2. Signed Divergence Field**  
### 🧩 **What it is**  
A scalar field that determines whether a pixel is:

- inside the shape (negative)  
- outside the shape (positive)  

### 🎯 **What it does**  
- Computes divergence of the gradient  
- Uses sign of divergence to determine “inside vs outside”  
- Produces a **signed scalar** per pixel  

### 🧠 **How it works logically**  
Divergence measures how much the gradient field is:

- **converging** (inside)  
- **diverging** (outside)

This gives you the **sign** of the distance.

### 📐 **Mathematical form**  
Divergence:

\[
\nabla \cdot \vec{g} = \frac{\partial gx}{\partial x} + \frac{\partial gy}{\partial y}
\]

Approximation:

```lua
div = (gx(x+1,y) - gx(x-1,y)) * 0.5
    + (gy(x,y+1) - gy(x,y-1)) * 0.5
```

Sign:

```lua
sign = div < 0 and -1 or 1
```

### 🧩 **FF map script prototype**
```lua
function divergence_sign(x, y)
    local gx1, gy1 = gradient_field(x+1, y)
    local gx2, gy2 = gradient_field(x-1, y)
    local gx3, gy3 = gradient_field(x, y+1)
    local gx4, gy4 = gradient_field(x, y-1)

    local div = (gx1 - gx2)*0.5 + (gy3 - gy4)*0.5
    local sign = div < 0 and -1 or 1

    return sign
end
```

This gives you the **sign** of the SDF.

# **3. Procedural Distance Accumulator**  
### 🧩 **What it is**  
A recursive or multi‑scale sampling method that estimates distance **without arrays**.

### 🎯 **What it does**  
- Uses the gradient direction to “walk” outward  
- Accumulates distance along the gradient  
- Produces a **distance‑like scalar**  
- Works at multiple scales  

### 🧠 **How it works logically**  
You repeatedly sample:

\[
(x_{n+1}, y_{n+1}) = (x_n, y_n) + \alpha \cdot \hat{g}(x_n, y_n)
\]

Where:

- \(\hat{g}\) is the normalized gradient  
- α is a step size  

You stop when:

- gradient magnitude is small (near boundary)  
- or after N steps  

Distance ≈ accumulated α.

### 📐 **Mathematical form**
Let:

\[
d = 0
\]

Loop:

\[
(x,y) \leftarrow (x,y) + \alpha \cdot \frac{\vec{g}}{||\vec{g}||}
\]
\[
d \leftarrow d + \alpha
\]

### 🧩 **FF map script prototype**
```lua
function distance_accumulator(x, y)
    local d = 0
    local steps = 8
    local step = 0.01

    for i = 1, steps do
        local gx, gy = gradient_field(x, y)
        local mag = math.sqrt(gx*gx + gy*gy) + 0.0001
        local nx, ny = gx/mag, gy/mag

        x = x + nx * step
        y = y + ny * step
        d = d + step
    end

    return d
end
```

This is a **procedural SDF approximation**.

### 1. Flow vector field (dx, dy, dz)

#### What it is  
A vector field derived from the input image that encodes:

#### What it does  
Turns any grayscale (or color‑derived) input into:

- a basis for erosion‑like streaking, directional smoothing, and shape‑aware warping.

#### How it works (logic)  
1. Compute gradient: ∂I/∂x, ∂I/∂y.  
2. Normalize to get direction.  
3. Use gradient magnitude as dz (or a function of it).

#### How it works (math)  
Let \(I(x,y)\) be the input intensity.

- Gradient:
  \[
  gx = \frac{\partial I}{\partial x}, \quad gy = \frac{\partial I}{\partial y}
  \]
- Magnitude:
  \[
  m = \sqrt{gx^2 + gy^2} + \epsilon
  \]
- Direction:
  \[
  dx = \frac{gx}{m}, \quad dy = \frac{gy}{m}
  \]
- Driver:
  \[
  dz = f(m) \quad \text{(e.g. } dz = k \cdot m \text{ or } dz = \frac{k}{m+\epsilon} \text{)}
  \]

function flow_vector(x, y)

    local c = sample(x, y)

    local cx1 = sample(x+1, y)
    local cx2 = sample(x-1, y)
    local cy1 = sample(x, y+1)
    local cy2 = sample(x, y-1)

    local gx = (cx1 - cx2) * 0.5
    local gy = (cy1 - cy2) * 0.5

    local mag = math.sqrt(gx*gx + gy*gy) + 0.0001
    local dx = gx / mag
    local dy = gy / mag

    return dx, dy, dz
end

A sampling scheme that offsets the lookup position along the flow vector instead of using random/noise offsets.

### 3. Pseudo‑iterative layering (fake erosion via octaves)

#### What it is  
A way to approximate iterative flow/erosion by stacking multiple flow‑guided samples with increasing step sizes, instead of true feedback.

#### What it does  
- Mimics material being transported along slopes.  
- Builds up streaks, channels, and directional wear.

#### How it works (logic)  
1. For each “layer” \(i\), choose a step size \(s_i\).  
2. Offset sampling along the same flow direction by \(s_i\).  
3. Blend all layers (e.g. average, weighted by dz, or distance).

#### How it works (math)  
For N layers:

\[
(x_i, y_i) = (x, y) + s_i \cdot dz \cdot (dx, dy)
\]
\[
O(x,y) = \frac{1}{N} \sum_{i=1}^{N} I(x_i, y_i)
\]

Or use non‑uniform weights.

#### Basic code
```lua
function pseudo_erosion(x, y)
    local dx, dy, dz = flow_vector(x, y)

    local steps = {0.01, 0.02, 0.04, 0.08}
    local acc = 0
    local wsum = 0

    for i = 1, #steps do
        local step = steps[i] * dz
        local sx = x + dx * step
        local sy = y + dy * step

        local w = 1 / (i)  -- simple weighting; can be dz-based too
        acc = acc + sample(sx, sy) * w
        wsum = wsum + w
    end

    return acc / wsum
end
```

---

## 🧩 What the epsilon term is doing  
The original line:

```lua
local dz = math.sqrt(gx*gx + gy*gy) + 0.0001
```

is doing **two** things at once:

- preventing division by zero when normalizing `(gx, gy)`  
- ensuring dz is never exactly 0, which would break any slope‑based driver logic  

This is the standard “epsilon trick” used in gradient‑domain math.

But it does **not** guarantee that `dz` stays within `[0,1]`.

---

## 🎯 What you’re proposing  
You suggested:

```lua
local dz = (math.sqrt(gx*gx + gy*gy) * 0.9999) + 0.0001
```

This does two things:

1. **Keeps dz strictly within (0.0001, 1.0)**  
2. **Still protects against division by zero**

This is a valid and mathematically clean normalization strategy.

---

## 🧠 When you *should* clamp dz  
You clamp dz when:

- dz is being used as a **driver** (step size, velocity, incline)  
- dz is being encoded into a **channel** (RGB, HSV, etc.)  
- dz is being used to **modulate noise** or **flow strength**  
- dz is being used in **pseudo‑iteration** (erosion‑like effects)  

In these cases, dz must be:

- bounded  
- predictable  
- stable  
- non‑explosive  

So yes — clamping is correct.

---

## 📐 The mathematically clean version  
If you want a normalized slope magnitude in `[0,1]`, the canonical form is:

```lua
local mag = math.sqrt(gx*gx + gy*gy)
local dz = math.min(1, mag) * 0.9999 + 0.0001
```

Or more compact:

```lua
local dz = math.min(1, math.sqrt(gx*gx + gy*gy)) * 0.9999 + 0.0001
```

This ensures:

- **dz never hits 0**  
- **dz never hits 1**  
- **dz is always safe to divide by**  
- **dz is always safe to multiply by**  
- **dz is always a valid channel value**  

This is the version I recommend for a **delta3** module.

---

## 🧭 Why you *don’t* always want to clamp  
If dz is being used as a **raw slope magnitude** (not normalized), clamping destroys information.

Examples:

- curvature estimation  
- erosion solvers  
- hydraulic flow  
- sediment transport  
- thermal weathering

**You can apply as many coordinate transforms as you want —  
but they must all be applied to the *same* (x,y) before the final sample.**

Meaning:

- You cannot remap → sample → remap → sample.  
- You *can* remap → remap → remap → sample.

This is the key.

### 1. Quick clarification: equirectangular vs Cartesian

- **Cartesian 2D:**  
  \((u,v) \in [0,1]^2\) interpreted as flat coordinates.  
  Cell size is uniform; area per cell is constant.

- **Equirectangular:**  
  \((x,y) \in [0,1]^2\) mapped to longitude/latitude:  
  \(\lambda = 2\pi(x-0.5)\), \(\varphi = \pi(y-0.5)\).  
  On a sphere, **area per texel shrinks by \(\cos\varphi\)** toward the poles.

So: same parameter domain, but **not** the same physical density on the sphere.

That’s the root of your “proportional density distribution” problem.

---

### 2. What you want: proportional density per unit area

For your “advanced/proposed Perlin,” the goal is:

> Features (cells, gradients, ridges) should have **roughly constant density per unit *surface area***, regardless of projection.

That means:

- in **Cartesian**: standard Perlin is fine.  
- in **polar**: cells should not bunch near the center.  
- on a **sphere**: cells should not stretch at equator and compress at poles.

So we need to either:

1. **Correct the domain** before feeding it to Perlin, or  
2. **Correct the frequency** locally based on the metric.

### 3. Fundamental idea: metric‑aware domain correction

For any mapping from parameter space \((u,v)\) to surface space, you can think in terms of a **local scale factor** \(s(u,v)\) that tells you how much area distortion you have.

Then:

- if you want **constant feature density**, you want noise to “see” a domain where area is uniform.  
- you can approximate this by **rescaling coordinates** by \(1/s\) or adjusting frequency by \(s\).

Let’s do this concretely for two cases you care about.

---

### 4. Polar noise: proportional cell density

Polar mapping:

- \(r \in [0,1]\), \(\theta \in [0,2\pi)\)  
- Cartesian: \(x = r\cos\theta\), \(y = r\sin\theta\)

Area element in polar:

\[
dA = r\,dr\,d\theta
\]

So near the center, area per \((dr,d\theta)\) is tiny; near the edge, it’s large.  
Standard Perlin in \((r,\theta)\) gives **too many features near the center**.

#### Simple density correction

You want a new radial coordinate \(r'\) such that area grows linearly:

\[
A \propto r'^2 \Rightarrow r' = \sqrt{r}
\]

So instead of:

```lua
local x = r * cos(theta)
local y = r * sin(theta)
```

you do:

```lua
local r2 = math.sqrt(r)
local x = r2 * cos(theta)
local y = r2 * sin(theta)
```

Then feed `(x,y)` into Perlin.  
This gives **more uniform feature density** across the disk.

---

### 5. Spherical/equirectangular: proportional cell density

Equirectangular mapping:

- \(\lambda = 2\pi(x-0.5)\)  
- \(\varphi = \pi(y-0.5)\)

Area element on sphere:

\[
dA = \cos\varphi \, d\lambda \, d\varphi
\]

So near the poles, area per \((dx,dy)\) shrinks by \(\cos\varphi\).  
Standard Perlin in \((x,y)\) gives **too many features near poles**.

**A. Sample noise in 3D Cartesian sphere coordinates**

You’re already doing:

Y = sin(lon) * cos(lat)
Z = sin(lat)
```

If you feed `(X,Y,Z)` into a **3D Perlin** with **isotropic frequency**, you automatically get **uniform feature density on the sphere**.

That’s the cleanest solution.

**B. Metric‑aware frequency scaling in 2D**

If you insist on staying in \((x,y)\), you can approximate:

- local scale factor \(s(y) \approx \cos\varphi = \cos(\pi(y-0.5))\)

Then:

- either scale coordinates:

- or scale frequency:

### 1. Core: perlin_implicit_sdf

Assume you already have:

```lua
-- core 3D Perlin, returns [-1,1]

    -- your implementation here
end
```

Now build the implicit SDF proxy:

```lua
-- finite-difference step in domain units
local H = 0.001

function perlin_implicit_sdf(x, y, z)
    -- base value
    local n0 = perlin3d(x, y, z)

    -- gradient via central differences
    local nx1 = perlin3d(x + H, y, z)
    local nx2 = perlin3d(x - H, y, z)
    local ny1 = perlin3d(x, y + H, z)
    local ny2 = perlin3d(x, y - H, z)

    local gx = (nx1 - nx2) / (2 * H)
    local gy = (ny1 - ny2) / (2 * H)

    local mag = math.sqrt(gx*gx + gy*gy) + 1e-6

    -- implicit signed-distance proxy
    local sdf = n0 / mag

    return n0, gx, gy, mag, sdf
end

### 3. perlin_divergence_driver

Divergence of the gradient ≈ Laplacian of `n0`. In FF, approximate with second differences:

```lua
function perlin_divergence_driver(x, y, z)
    local n0  = perlin3d(x, y, z)
    local nx1 = perlin3d(x + H, y, z)
    local nx2 = perlin3d(x - H, y, z)
    local ny1 = perlin3d(x, y + H, z)
    local ny2 = perlin3d(x, y - H, z)

    local d2x = (nx1 - 2*n0 + nx2) / (H*H)
    local d2y = (ny1 - 2*n0 + ny2) / (H*H)

    local div = d2x + d2y
    return div
end
```

Use `div` as:

- positive → “sources” (peaks)  
- negative → “sinks” (valleys)
